# WSL2 smoke vs the Windows smoke (2026-10-27, same RTX 3050 A Laptop)

Question: does running the patched llama.cpp stack inside Ubuntu on WSL2 lose speed versus the Windows run on this GPU?

Command: `scripts/reproduce.sh --build --smoke` (1 timed pass, 64 tokens, one discarded warm-up, fresh server per config). No `nvcc` in WSL, so the script used the hybrid build: llama.cpp b11884 host code plus both patches, linked against the official Ubuntu CUDA **12.8** libraries (`libggml-cuda.so`, cuBLAS, cudart). The Windows smoke (`reproduce-out/reproduce-20261027-170014.md`, cited in [`2026-10-27-reproduce-check.md`](2026-10-27-reproduce-check.md)) used the hybrid MSVC build plus the official Windows CUDA **12.4** DLLs. Same model file, same prompts, same flags (`-ngl 99 -fa on -np 1 -kvu -c 4096`, greedy). GPU idle before the run (0% util, 0 MiB). Driver 592.82. A load of this server held about 1.7 GiB of VRAM; plain decode was ~15.5 ms/token, not the ~11 tok/s CPU fallback seen earlier when CUDA was unavailable.

| config | Windows tok/s | WSL2 tok/s | WSL / Windows | vs own plain | acceptance |
|---|---:|---:|---:|---|---|
| code plain | 68.17 | 64.85 | 0.951 | 1.00x / 1.00x | - |
| code MTP, 32k trim | 119.16 | 117.54 | 0.986 | 1.75x / **1.81x** | 65.9% / 65.9% |
| copy plain | 68.24 | 63.73 | 0.934 | 1.00x / 1.00x | - |
| copy MTP, 8k trim | 150.97 | 144.23 | 0.955 | 2.21x / **2.26x** | 89.2% / 89.2% |
| copy n-gram + MTP | 220.94 | 212.57 | 0.962 | 3.24x / **3.34x** | 64.6% / 64.6% |

"vs own plain" is Windows ratio / WSL ratio. Acceptance is Windows / WSL.

Absolute tok/s on WSL2 were **1.4% to 6.6% lower**. The biggest gap is plain copy-heavy (6.6%); the headline code config was 1.4% lower. Draft acceptance matched the Windows smoke on every speculative config, and byte-identical-to-plain was 4/4 (code) and 6/6 (copy) on both sides. Speed-up ratios were slightly higher on WSL because plain decode dropped a bit more than the speculative configs.

That gap sits next to the ~5% session drift already seen on Windows (plain bf16 65–68 tok/s). This was one smoke pass of 64 tokens, and the CUDA runtime was 12.8 on WSL versus 12.4 on Windows, so it is not a pure WSL-versus-Windows measurement. It is enough to say there is no large WSL penalty: the headline speed-ups still show up. The full 3-pass, 256-token run was not repeated under WSL.
