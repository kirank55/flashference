# Scaling experiments, Qwen3.5-0.8B only (2026-10-26)

Scope of this file: the 0.8B parts of [docs/PLAN-single-reply.md](../docs/PLAN-single-reply.md) (S1, S2a/S2b, S3). Larger models (2B, 4B) and Qwen3 are **not** covered here. ## S1. Speed vs bits per weight, with the quality cost (0.8B only)

**Method.** 9 extra quants were downloaded from bartowski/Qwen_Qwen3.5-0.8B-GGUF (names verified with the HF API): Q2_K, IQ3_M, Q3_K_S, Q3_K_M, IQ4_XS, Q4_0, Q4_1, Q4_K_S, Q5_K_S; together with the 5 existing files that is 14 files. Speed: `llama-bench -ngl 99 -fa 1 -p 512 -n 256 -r 5` (llama-bench's own warm-up on; 5 repetitions each), in ascending file-size order (pass 1), then the whole table again in reverse order (pass 2, same session) as the drift control. Quality: `llama-perplexity -c 512 --chunks 20 -ngl 99 -fa on` on the first 20 chunks of wikitext-2-raw **test** (about 10k tokens; file from ggml-org/ci on Hugging Face); bf16 logits saved with `--kl-divergence-base`, then every quant run with `--kl-divergence` (supported by this build). Scripts: `scripts/s1_quants.py`, `scripts/s1_report.py`; raw data `results/2026-10-26-s1-quants-0.8b.raw.json`.

Columns: bits/weight = file bytes * 8 / 772.85 M parameters (as reported by llama-bench; includes the token-embedding matrix, which is a large part of this model, and the unused MTP block). "decode mean (SD)" pools the two passes (mean of the two means; SD = the larger of the two). "vs Q8_0 / vs bf16" = ratio of pooled decode tok/s. PPL is on only ~10k tokens, so its standard error (+/- 0.8) is much larger than the differences between most quants; **use KLD and same-top-token as the quality measure** (they are paired with the bf16 run on the same tokens). Drift between pass 1 and pass 2 was within 0.6% for every file (<= 3% threshold, no redo needed). SDs are 0.1-1.2 tok/s (<1% of the mean), so differences above ~2.5 tok/s (2 x pooled SD) are real for this session; closely spaced pairs (e.g. Q4_K_S 161.6 vs IQ4_XS 161.9) are not distinguishable.

### Reading S1 (see FINDINGS.md section 9 for the tagged conclusions)

- Decode speed rises monotonically with *fewer bytes* only roughly: bf16 71.5 -> Q8_0 121 -> Q4_K_M 155 -> Q4_0 171 -> Q2_K 177 tok/s. Q4_K_M vs Q8_0 is **1.28x** (file-byte ratio 1.45x), Q4_K_M vs bf16 2.17x (byte ratio 2.72x). The speed gain per saved byte falls as files shrink: from Q4_K_M to Q2_K the file is 20% smaller and decode only 14% faster.
- File size alone does **not** predict speed between formats: Q3_K_M (484 MiB, 149.5 tok/s) is slower than Q4_0 (502 MiB, 170.6) and IQ3_M (474 MiB, 164.1); Q3_K_S (470 MiB) is 152.0. So per-format dequantisation work matters, not just bytes streamed. A straight line `t_token = a + b * file_GB` fits the 14 files with R^2 = 0.98 only because bf16 anchors it; without bf16 R^2 = 0.83 (see fit table). The intercept a (~2.3-3.1 ms/token, i.e. ~40-50% of the Q4_K_M token time of 6.45 ms) is the size-independent per-token cost; the implied slope 1/b is ~120-160 GB/s of effective weight streaming [fit artefact, not a bandwidth measurement].
- Prefill (pp512) is compute-bound and nearly independent of bits: 7.7-9.2k tok/s for all quants, 6.9k for bf16.
- Quality: mean KLD vs bf16 rises from 0.0013 (Q8_0) through 0.0101 (Q5_K_M), 0.0303 (Q4_K_M), 0.074 (Q4_0), 0.122 (Q3_K_M) to 0.416 (Q2_K); same-top-token falls from 97.9% to 66.9%. Q2_K is not usable (PPL 29.0 vs 19.1). At comparable size the format matters: IQ4_XS (488 MiB) has lower KLD (0.050) than Q4_0 (502 MiB, 0.074) and is slightly slower (161.9 vs 170.6); Q4_K_M is the best quality/speed point in the 4-bit band for this model (KLD 0.030, 1.28x Q8_0).
- Best speed per KLD ("knee"): Q8_0 -> Q4_K_M costs 0.029 KLD for +28% speed; Q4_K_M -> Q4_0 costs +0.043 KLD for +10%; Q4_K_M -> Q2_K costs +0.386 KLD for +14%.
- Caveat: only one model size, one machine, ~10k wikitext tokens; bartowski publishes an imatrix file in the repo, so the low-bit files are probably imatrix-calibrated [assumption, not verified]. Whether the order generalises to other sizes needs the 2B/4B runs (not done in this run).
